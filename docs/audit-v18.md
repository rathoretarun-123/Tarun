The user asked, at v18: "read all the instructions given from starting and check if the app follows them in letter and
spirit, if not, try again, if impossible give a proper explanation." This is that check. The instructions are taken
from the seventy user messages of the project's conversation (the first APK, "Tarun Video Studio v4", came from an
earlier chat; its errors were the first list), from the commit history and from the README's version notes.

"Where" names the code (`core/` = `app/src/main/java/com/tarun/kahani/core`, `app/` = `…/app`) and the test that
exercises it (`tools/robotest/…/AppTest.java`, 15 tests).

## 3. What was tried again at v18 because the earlier version did not fully satisfy the letter

* **"A separate library, not the camera library" (v11, repeated at v18 as "tarunkahani")** — v11 kept the library private
  (inside the app, with a private backup). v18 names the app's own library "tarunkahani" and keeps every picture the app
  receives or makes there (with a private backup in Downloads/tarunkahani) — never in the camera or photos library, as
  the user asked again at v18 ("not in my camera library or photos library").
* **"Create Vanusha's backside picture"** — v17 could only turn its own dolls; v18 turns the user's picture itself.
* **"One picture per shot"** — the first frame of every shot is now saved with the film, named by its shot ID, and the
  reverse shots, walks and two-shots use the views.
* **"10-minute film in 30 minutes" against "pixel-level meshes"** — the user chose pixel level repeatedly; v18 keeps it as
  the default and adds the faster-drawing switch so the earlier ask can be met on a slow phone by choice.

## 4. What cannot be done, and why

| Ask | Why not | What is offered instead |
|---|---|---|
| Keys for paid or rate-limited services built into the app | the code is public; a built-in key is stolen and revoked within days | one clearly labelled field per tool in Settings; keyless defaults for everything |
| A true Pixar-class 3D film from a script and a few pictures on a phone | a feature film is modelled, rigged, animated and rendered in full 3D by teams on render farms; a phone bending pictures cannot become that | every rule of the protocols and guides applied and measured; 3D-style pictures, Studio 3D, the figure model, the two-light finish, locked shots, lip-sync in close-ups, the frame-by-frame check |
| Cloning a voice from a sample on the phone | needs a trained cloning model (hundreds of megabytes and a GPU, or a paid service) | voice matching (pitch, speed, timbre) on the most natural free voices; ElevenLabs with the user's own key |
| A learned image-to-3D network inside the app | training needs data and GPU days; running one on a phone keyless is not possible at this size | the geometric and photometric figure model; an image-to-3D service with the user's key |
| Seeing the back of a character from one front picture exactly | the picture does not contain it | the costume going round and the top of the head coming down; the user's own back picture wins (eleven real ones ship with the sample) |
